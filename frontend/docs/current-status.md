## 구현 상태

현재 화면은 React·React Router·Vite 기반이다. 기본 모의 모드에서 질문 분기·예시 답변·조문·추적·문서 등록·평가는 브라우저 내부 모의 동작이다. 상담 스트림·PDF 등록·단일 실험 평가 결과 조회의 API 클라이언트와 개발 프록시는 구현했다. 실제 FastAPI·DB·외부 모델로 끝까지 실행하는 검증과 구조화 근거 연결은 남아 있다. 고정 점수·소요시간·건수는 실측값이 아니다.

핵심 기능은 법령 AI 상담, 법령 RAG 관리, Opik 평가 세 가지다. 현재 6개 페이지는 이 기능과 검토 도구를 나눈 구성이다. 초기 요구사항과 사용자 확인에 따른 React 기반 화면 구성 요구를 코드에 반영했다. 여섯 화면을 React 렌더링·상태·이벤트로 이식했고 이전 HTML 컨트롤러 의존을 제거했다. 원래 목업은 frontend 밖의 전환 기준본으로 보존했다. 요구사항 대응표의 55개 항목도 전부 구현했거나 모두 이번 제출 범위로 확정했다는 뜻은 아니다.

검토 기준 백엔드는 ChromaDB 검색, Ollama의 nomic-embed-text 임베딩, Elice 외부 API 생성 코드가 있다. Opik 관련 팀 작업은 공유 기록에 있으나 기준 저장소에서는 재실행 가능한 평가 코드·결과를 확보하지 못했다. 코드 위치·결과 형식을 확인해야 하며 현재 모의 점수·추적값은 실제 평가 결과와 연결돼 있지 않다. 이미지의 Ollama LLM·JSON 응답 구상과 실제 코드를 구분한다.

## 현재 API 계약과 연결 원칙

아래는 기준 코드 검토 결과이며 실제 서버·외부 모델 호출 검증은 아직 하지 않았다.

| 경로 | 요청 | 현재 성공 응답·제약 |
|---|---|---|
| POST /ask/chat | JSON의 필수 문자열 q · 상담 법령 고정 | text/plain 스트림. JSON·SSE·구조화 근거 배열이 아님 |
| POST /upload | multipart/form-data의 subject, file | `{"upload":["파일명.pdf"]}`. 청크 수·조문 수·문서 ID는 반환하지 않음 |

- 상담 법령은 서버 고정값을 따른다. PDF 등록 subject는 등록 화면에서 별도로 설정하며 상담에 영향을 주지 않는다.
- 일반 텍스트 스트림은 UTF-8 점진 디코딩으로 누적하며 표시한 답변 전체를 보존한다. 서버 텍스트를 실행 가능한 HTML로 삽입하지 않는다.
- 현재 스트림 종료에는 생성 종료 사유·완료 상태 계약이 없다. EOF만으로 모델이 정상 완결했다고 단정하지 않는다. 네트워크 실패와 부분 답변을 함께 보존한다.
- 실제 근거를 받기 전 고정 목업 조문·점수·추적을 실제 응답에 붙이지 않는다. 첫 연결은 실제 답변 전체 표시부터 가능하다.
- 업로드는 같은 subject를 재등록하면 기존 subject 청크를 교체한다. 파일 저장 후 색인 실패 시 파일이 남아 같은 이름 재시도가 막힐 수 있다. 오류·교체·복구 계약 보완 필요.
- 서버 실행에는 Python 의존성, Chroma 데이터, 임베딩 서비스와 외부 API 설정이 필요하다. Vite 개발 서버만으로 Python 백엔드가 실행되지는 않는다. 화면과 FastAPI의 origin이 다르면 배포 방식·프록시·CORS를 함께 정한다.
- 제안한 /api/chat/stream·문서/조문/실행 조회·평가 실행 API는 아직 구현된 경로가 아니다. 필요한 확장은 실제 검색 본문, 검증된 인용·상태, 종료·오류, 실행 기록, 업로드 결과다. 전부 먼저 만들 필요는 없다.
- frontend는 현재 Git 코드에 맞춰 독립적으로 연결 준비를 할 수 있다. 공통 백엔드 계약을 바꿀 부분은 정소미와 맞추고 평가 데이터·지표는 분석 담당과 맞춘다.
