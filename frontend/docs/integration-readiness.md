# 연동 실행 기준과 팀 확인 목록

확인한 코드와 실행 환경을 구분한다. 아래 미확인은 실제 환경 확인 후 채우며 추정값으로 완료 처리하지 않는다. 원격 최신 상태나 팀원 PC 작업물의 전체 목록을 보증하는 문서가 아니다.

| 항목 | 코드/공유 자료 기준 | 실제 실행 확인 |
|---|---|---|
| 기준 커밋 | main `65d379de6001bad69322b8f30e9e896a77295a84` | 팀 채택 커밋 확인 필요 |
| 상담/등록 경로 | `/ask/chat`, `/upload` | 실제 호출 미검증 |
| 기본 개발 대상 | `http://127.0.0.1:8000` | 실행 주소 확인 필요 |
| 서버 작업 디렉터리 | 프로젝트 최상위에서 실행하는 절차 권장 | 실제 프로세스 경로 미확인 |
| DB·업로드 위치 | 작업 디렉터리 기준 `./store`, `./upload` | 실제 절대 경로 미확인 |
| 컬렉션 | `lecture` | 사용 DB 확인 필요 |
| subject | 상담: 산업안전보건기준에 관한 규칙으로 고정 | PDF 등록 subject는 별도 입력 |
| 기준 PDF | 산업안전보건기준에 관한 규칙, 제450호, 2026-03-02 | 실제 적재 파일 해시 대조 필요 |
| PDF SHA-256 | `a4031561fcc8f8b83676f7852e4d226ba0c39246de40438b8110a52f60ca0c59` | 같은 파일인지 확인 필요 |
| 임베딩 | main: nomic-embed-text:latest / Ollama | 이슈의 bge-m3 변경과 채택 기준 확인 |
| 검색/청킹 | Dense, Top-5, subject 필터, 1500자/겹침200자 | BM25는 별도 실험. 배포 방식 확인 |
| 생성 | main: Elice 외부 API / ELICE_MODEL 설정 | 실제 모델명·접속 확인 필요. 비밀값 기록 금지 |
| 적재 건수 | 팀 실험 684청크 | 사용자 DB 실측값 아님 |
| 평가 | LAW 개발15/최종15, 실제 결과 형식 미연결 | 코드/결과 또는 Opik 조회 방식 확인 |

전달받은 구조도의 Ollama LLM·JSON 응답은 현재 main의 외부 생성 API·text/plain 스트림과 다르다. 채택 기준이 확정되면 구조도와 실행 문서도 맞춘다. 모델을 바꾸면 그 모델과 맞는 색인을 사용한다.

## 단독으로 확인 가능한 것

- 현재 계약의 전송 형식, 프런트 입력·오류·부분 수신 안내, 실제/모의 구분.
- `npm.cmd test`, `npm.cmd run build`, 빌드 제공 및 격리 시험 서버 프록시 검사.
- 브라우저 접근이 가능한 환경의 화면·키보드·좁은 화면·콘솔 확인.
- 현재/확장 계약 문서와 확인 목록 작성. 명세 초안은 [api-contract.md](api-contract.md).

## 실호출 전제

상담은 서버 주소·고정 법령의 DB·모델이 확인된 뒤 개발용 단일 질문으로 확인한다. 문맥/Agent 시험은 별도다. 비밀 키는 백엔드 환경에서만 관리한다.

등록은 별도 DB와 업로드 절대 경로를 확인한 환경에서만 시험한다. subject 변경만으로 격리되지 않으며 파일명 충돌은 subject와 무관하다. 현재 코드에 없는 DB 환경변수를 추가하는 것만으로 경로가 바뀌지는 않는다. 실제 환경이 없으면 프런트 준비 완료·실호출 미확인으로 남긴다.

## 팀원별 확인 항목 — 메시지 초안용

| 대상 | 필요한 자료/결정 | 받은 후 박상진 작업 |
|---|---|---|
| 정소미 | 실행 커밋·주소·subject·DB/파일 경로, nomic/bge 채택과 색인 기준 | 실행표 확정 및 기본 상담 검증 |
| 정소미 | 동일 실행의 검색 Document/메타데이터 예시, 실제 적재 집계 | 합의한 응답에 맞춘 근거·집계 표시 연결 |
| 정소미 | 동명·중복·교체 단위와 실패 복구 정책 | 등록 안내·오류·결과 확인 절차 반영 |
| 김민석 | 검색 결과 예시, Hit@K/MRR 정의·판정 단위·실험 설정 | 결과 표시 및 비교 단위 일치 |
| 김유진 | 평가 입력/출력 예시, 지표 척도·방향·실패/제외, Opik 접근 방식 | 실제 평가 결과 연결 |
| 분석 담당 공동 | 유형별 검증 범위와 기존 최종문항 열람 이력 처리 | 개발 테스트/최종 평가 구분 유지 |
| 개발 공동 | 확장 응답 방식·경로, 요청/실행 ID 연결, 배포 방식 | 프록시·클라이언트·배포 검증 반영 |

Agent·세션 담당과 구현은 이번 단독 작업에서 제외한다. 해당 요구사항이 삭제된 것은 아니다. 이 문서를 만든 사실은 팀에 전송하거나 역할·계약을 확정한 사실과 다르다.

## 완료 기준

현재 두 API의 필드/형식 호환, 정상·오류 수신 처리, 실제/모의 구분, 변경부 검사, 미확정 계약의 예시와 확인 목록이 있으면 독립 준비 작업 완료다. 실근거·평가·실모델 연동 완료는 실제 자료와 실행 증거를 확보한 경우에만 표시한다. 최종 브라우저 및 실호출 확인 결과는 현재 상태 문서와 별도 수행 결과를 함께 확인한다.
